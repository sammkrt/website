01 / SELECTED WORK

Selected production engineering

My work at Crowdtech goes beyond implementing endpoints. I contribute across application state, identity, data, deployment, and production stability for survey and community platforms.

01PLATFORM ARCHITECTURE

Removing server-bound session state

Refactoring import and export workflows so they could operate reliably across multiple application servers.

.NET 8ASP.NET CoreCachingState managementRefactoringAcceptance testing
Inside the work

The challenge

Parts of the survey platform depended on HttpContext.Session. In a multi-server environment, this tied workflow state to a particular web server and made behaviour harder to predict when requests moved between servers.

My contribution

I worked on removing the session dependency from import and export workflows. The new approach used explicit state management and cache-backed storage. My work also included acceptance testing of the migrated workflows.

Why it matters

Application state has a clearer owner, and the workflows are better suited to a load-balanced environment.

02SECURITY & IDENTITY

Strengthening authentication behaviour

Improving authentication reliability and reducing information leakage across identity flows.

ASP.NET CoreOpenIddictEntra IDAuthenticationAuthorizationTiming consistency
Inside the work

The challenge

Authentication behaviour depended on several application and infrastructure settings. Small configuration differences could interrupt login flows, while inconsistent response timing could reveal whether a user account existed.

My contribution

I investigated authentication failures across environments, worked on OpenIddict and Entra ID integration issues, and contributed to constant-time handling that reduced the risk of user-enumeration through response timing.

Why it matters

Authentication should behave consistently without revealing unnecessary information about users or internal configuration.

03DELIVERY & OPERATIONS

Safer multi-server deployments

Supporting a staged deployment approach for an IIS and Application Request Routing environment.

Azure DevOpsIISARRPowerShellHealth checksTraffic drainingStaged deployment
Inside the work

The challenge

Deploying to several production web servers requires coordinating application availability, traffic routing, health checks, and differences between server environments.

My contribution

I worked with a staged deployment approach in which traffic could be drained from selected servers, a release could be applied and validated, and capacity could be returned gradually. I also investigated deployment failures and environment-specific behaviour.

Why it matters

A controlled rollout makes failures easier to isolate and reduces the operational risk of releasing to all servers simultaneously.

04CLOUD CONFIGURATION

Loading secrets at the correct startup stage

Resolving an authentication failure caused by application configuration being loaded too late.

Azure Key VaultEntra IDASP.NET Core configurationDependency initializationProduction debugging
Inside the work

The challenge

After authentication secrets were moved into Azure Key Vault, an application could no longer complete its login configuration because the required values were unavailable when authentication services were initialized.

My contribution

I traced the failure through the application startup sequence and corrected when the Key Vault configuration was loaded, making the authentication settings available before the dependent services were registered.

Why it matters

Secret management only works reliably when configuration is available at the point where dependent services are created.

05DATA INFRASTRUCTURE

Consolidating database environments

Supporting the migration of an acceptance environment to a consolidated SQL Server setup.

SQL ServerLinked serversConfiguration managementEnvironment migrationValidation
Inside the work

The challenge

Applications and database routines depended on connections between several database environments. Consolidation required updating those dependencies without leaving active connections to the previous environment.

My contribution

I worked on updating the relevant database connections and linked-server configuration, validating the acceptance environment, and helping retire the previous setup after verification.

Why it matters

Consolidation reduces configuration drift and makes the data environment easier to operate and maintain.

06DATA PRIVACY

Privacy-aware data retention

Working on anonymization and retention behaviour while preserving valid relationships between survey and community data.

.NETSQL ServerGDPR-related retention behaviourAnonymizationRetention policiesRelational data integrity
Inside the work

The challenge

Removing or anonymizing personal data must respect privacy requirements while preserving the non-personal relationships the platform still needs for correct operation and reporting.

My contribution

I worked on unsubscribe, anonymization, and retention behaviour, including cases where survey and community records remained related after personal information was removed.

Why it matters

Privacy features need to protect personal information without damaging the structural integrity of the remaining platform data.
